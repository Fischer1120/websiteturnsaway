# Royal Lime Archive 原型说明

## 查看原型

入口是 `index.html`。可以直接在浏览器打开，也可以从项目根目录启动本地服务：

```bash
python3 -m http.server 4173 --bind 127.0.0.1 --directory 'design/concepts/concept-05-royal-lime-archive'
```

访问 [本地预览](http://127.0.0.1:4173/#/home)。后台入口位于顶部导航，点击“进入演示后台”即可，不需要管理密码。

所有编辑只保存在当前页面的内存中。刷新后恢复两篇文章、两张图片和四个文件夹。演示退出不会上传、发布或删除生产内容。

## 设计

白色作为主体背景，宝蓝 `#2448FF` 用于主操作、导航选中态和首页视觉区，黄绿 `#D7F542` 用于编号牌、选中标签和未保存提示。文章采用横向索引，图片采用错落网格，阅读页保留充足留白。

字体沿用现有宋体、黑体和等宽字体栈，不请求外部字体。窗口较窄时，公开页面改为单列，后台在记录列表和编辑器之间切换。减少动态效果的系统设置和原型动效开关都受支持。

正文与白底的对比度为 17.57:1，次要文字与浅灰底为 5.57:1，白字与宝蓝为 6.09:1，宝蓝与黄绿为 4.94:1。常用文字组合均达到 4.5:1。

## 页面与使用流程

- 首页：欢迎词、文章、图片和四个文件夹入口。
- 文章：全部列表、按文件夹浏览、两篇完整正文、章节目录及插图。
- 图片：全部列表、相册、独立详情、拍摄时间、地点、相机信息及图下描述。
- 地图：本地街区示意、点位与照片联动、加载、失败和重试。
- 后台文章：新建、编辑、Markdown 预览、光标插图、保存和单条删除。
- 后台图片：新增本地图片、元数据编辑、EXIF 演示、保存和单条删除。
- 后台文件夹：创建、修改显示名称和删除空文件夹；非空文件夹不能删除。

文件夹标识使用小写英文、数字和短横线。同类内容中的标识不可重复，文章和图片之间允许相同标识；显示名称允许重复。标识创建后固定，已有图片的所属文件夹保持固定。

编辑后，切换记录、栏目或页面会提示是否放弃修改。浏览器前进、后退以及直接修改页面地址中的 hash，也经过同样的检查。取消会保留当前内容和地址。

## 演示状态

点击“调整预览”，可以改变信息密度、关闭动效、模拟地图加载失败、模拟保存失败，以及切换 EXIF 状态。关闭面板后再操作页面。

地图只是位置示意，不加载实际瓦片，也不依据精确坐标绘图。EXIF 不解析文件，而是展示读取中、成功、无数据和失败四种界面；成功状态仅为未手动编辑的字段填入演示信息。位置精度菜单与现有后台保持一致：城市级、附近区域和精确位置。

文章插图与图片上传支持 PNG、JPEG 和 WebP，通过浏览器本地对象地址显示。Markdown 支持标题、段落、列表、引用、代码和独立成行的图片；插入图片时会补齐段落换行。输入的 HTML 不执行，外部图片地址不会被加载。

## 内容来源与实现边界

两篇文章和两张图片的内容取自仓库种子文件，保留正文、时间、地点、相机信息和替代文本。画面是仓库现有 SVG 示例插图，并非新增实拍摄影。素材复制到本目录，原文件没有更改。

原型采用原生 HTML、CSS 和 JavaScript，只有本地资源，没有新增依赖、API、存储结构或生产路由。所有页面使用 hash 路由，支持直接打开与刷新。此目录独立于正式网站；提交原型源码不会将这套页面接入生产路由。本轮未执行部署。

Luna 参与了计划保存和初始页面制作；用量限制中断后，由协调 agent 接续完成模块整理、页面实现和浏览器验证。独立审核发现的问题及复核结果记在 `review.md`，实际任务状态记在 `progress.md`。

## Astra 设计优化

Astra 复查了页面美学和响应式布局。首页缩窄宝蓝画框，完整展示几何建筑；桌面文章封面加大，手机改为右侧缩略图；照片按自然比例展示。文章标题与正文对齐，手机目录默认收起，后台用选中栏目承担主要色彩，避免通高蓝栏分散注意力。

详细设计判断见 [Astra 设计说明](astra-design-notes.md)，本轮独立复核见 [Astra 审核报告](astra-review.md)。下面的检查结果与27张正式截图已在优化后重新生成。

## 验证记录

验证使用 Chromium 和本地 HTTP 服务完成，另检查了直接打开本地 HTML 的首页及演示后台。

- 公开页面与主要流程：135 项检查通过。
- 图片、EXIF、插图、手机后台和键盘操作：32 项补充检查通过。
- 首页、列表、文件夹和详情覆盖 1440、1024、390、320px 宽度，无横向溢出。
- 检查了文章保存同步、未保存离开与后退取消、保存失败保留草稿、单条删除、非空文件夹保护和地图重试。
- 检查了重复选择同一图片、文首插图、选区替换、EXIF 手填保护、图片新增与删除、手机列表和编辑器切换。
- 最终截图采集过程中，没有控制台错误、警告、资源加载失败或外部请求。
- 148 个原有文件与实施前的 SHA-256 校验值一致。

详细结果位于 `output/playwright/verification-public.json`、`verification-editor.json`、`screenshots.json`、`contrast.json` 和 `baseline-check.json`。同目录保留验证脚本；这些脚本通过 Playwright CLI 的 `run-code` 执行，不是独立 Node.js 测试程序。执行时以本原型目录为工作目录，图片输入和截图输出使用相对路径。临时浏览器日志通过本目录的 `.gitignore` 排除，不随源码提交。

生产构建、生产接口测试、真实地图服务和真实 EXIF 解析不属于本次原型验证范围。
