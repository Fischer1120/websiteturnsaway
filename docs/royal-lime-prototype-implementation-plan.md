## 二、给 Luna 的执行规则

### 1. 每次只处理一个任务

执行顺序：

1. 阅读本任务的输入和验收条件。
2. 检查相关文件当前状态。
3. 完成本任务允许的修改。
4. 执行本任务对应的验证。
5. 更新进度记录。
6. 验证通过后进入下一任务。

不要在制作页面时同时改路由、后台状态和全局视觉系统。

### 2. 进度记录

在原型目录维护 `progress.md`，每项采用以下格式：

```markdown
## T01：任务名称

- 状态：未开始 / 进行中 / 已完成 / 阻塞
- 修改文件：
- 已执行验证：
- 验证结果：
- 遗留问题：
- 下一任务：
```

“已完成”必须有实际验证结果。代码写完但未打开浏览器的页面，应记录为“进行中”。

### 3. 模型与角色

- 前端设计子 agent 使用 Luna，并读取 `web-design-engineer` 技能。
- 总协调 agent 负责分配任务、核对进度和整理交付。
- 独立审核子 agent 不得是制作原型的同一 agent。
- 审核时使用新上下文，仅提供本计划、原型成品文件和验收要求。
- 中文说明文档使用 `humanizer-zh` 整理，沿用仓库普通 Markdown 格式。

### 4. 遇到问题时

- 同一问题连续两次修复无效，先记录复现步骤和错误，再单独诊断。
- 不通过升级依赖、重写生产模块或引入新框架解决原型问题。
- 无法完成的检查标明原因，不写“通过”。
- 缺少真实数据时，复用仓库示例；额外演示记录必须标注为示例。

## 三、固定设计与技术方案

### 1. 视觉规格

| 项目 | 固定方案 |
|---|---|
| 页面底色 | 白色 `#FFFFFF` |
| 辅助表面 | 浅灰 `#F3F4F6` |
| 正文 | 深墨色 `#17191F` |
| 次要文字 | 灰色 `#5C626D` |
| 分隔线 | 浅灰 `#DDE1E7` |
| 主要点缀 | 宝蓝 `#2448FF` |
| 撞色 | 黄绿 `#D7F542` |
| 圆角 | 0、2、4px 三档 |
| 间距 | 4、8、12、16、24、32、48、64px |
| 动效 | 150–220ms；支持减少动态效果 |
| 内容宽度 | 最大 1440px，居中 |
| 正文 | 16–18px；文章行高约 1.8 |
| 标题字体 | 沿用现有宋体字体栈 |
| 正文字体 | 沿用现有黑体字体栈 |
| 元数据字体 | 沿用现有等宽字体栈 |

界面中性色约占 80%，宝蓝约占 15%，黄绿约占 5%。这是构图参考，摄影内容自身颜色不计入。

**用色规则：**

- 宝蓝用于主按钮、选中导航、栏目编号和少量实色区域。
- 黄绿用于重点标签、局部底色及主视觉周边的色面对照。
- 黄绿底使用深色文字；不使用白底黄绿小字。
- 错误状态使用明确的图标或文字和边框提示，不能只靠颜色区别。
- 图片内容保持原色，不通过滤镜强行改成蓝绿色。

### 2. 页面构图

- 首页取消旧版厚重的深色外框和持续占宽的侧栏，使用横向导航、非对称主视觉及分区内容。
- 文章列表使用编号、标题摘要和封面组成的条目。
- 图片列表使用疏密有节奏的网格，保持图片比例。
- 文章详情提供安静的白色阅读区。
- 图片详情以大图为主，桌面元数据置右，描述位于图下。
- 后台采用“栏目导航＋记录列表＋编辑区”，移动端切换为列表和编辑器两个界面。

### 3. 技术选择

采用原生 HTML、CSS、JavaScript。

- 不增加 npm 依赖。
- 使用普通 `defer` 脚本，避免本地文件模式下 ES Module 和 `fetch` 的限制。
- 使用 hash 路由，支持直接打开子视图、刷新、前进和后退。
- 示例数据随脚本加载。
- 后台修改只保存在内存，刷新恢复初始数据。
- 原型退出登录仅切换演示会话状态，不涉及真实鉴权。
- 不新增公开 API、生产类型或数据库结构。

### 4. 文件划分

```text
concept-05-royal-lime-archive/
  index.html
  base.css
  public.css
  admin.css
  responsive.css
  data.js
  app.js
  public.js
  admin.js
  preview.js
  assets/
  screenshots/
  notes.md
  progress.md
  review.md
```

职责固定：

- `index.html`：页面容器、公共导航、对话框容器。
- `base.css`：颜色、字体、按钮、表单、公共布局。
- `public.css`：首页、文章、图片、地图。
- `admin.css`：后台布局和状态。
- `responsive.css`：各断点布局调整。
- `data.js`：种子内容与初始数据。
- `app.js`：路由、导航、公共焦点和离开确认。
- `public.js`：公开页面渲染、地图状态。
- `admin.js`：后台编辑及内存中的增删改。
- `preview.js`：原型调整面板及演示状态开关。

脚本按上述依赖顺序加载。共享入口集中放在 `window.ArchivePrototype`，不散落多个全局状态对象。

### 5. 原型路由

| 路由 | 内容 |
|---|---|
| `#/home` | 首页 |
| `#/articles` | 全部文章 |
| `#/articles/notes` | 文章文件夹 |
| `#/articles/notes/monolith-at-sunset` | 文章详情 |
| `#/images` | 图片列表 |
| `#/images?view=map` | 地图 |
| `#/images/city-walk` | 图片文件夹 |
| `#/images/city-walk/20260531-184200-a1b2` | 图片详情 |
| `#/admin` | 后台入口 |
| `#/admin/articles` | 文章管理 |
| `#/admin/images` | 图片管理 |
| `#/admin/folders` | 文件夹管理 |

另一篇文章和另一张图片使用相同规则。未知路径显示简洁的“页面不存在”和返回首页入口。

页内目录使用独立的目标标识处理，不与页面 hash 路由混用。
